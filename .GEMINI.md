## 2. DEFENSIVE CODING & BUG PREVENTION PLAYBOOK

Before declaring any change complete, rigorously audit against these critical vectors:

### 2.1 Type & Runtime Safety (PHP 8.2 / 8.3 / 8.5 & Modern Stacks)
- Strictly enforce type boundaries. Never pass `null` to non-nullable native functions (`strlen`, `substr`, `preg_replace`).
- Guard all array access and object properties with null-coalescing (`??`) or explicit existence checks.
- Handle database empty sets and missing relational records gracefully with fallbacks (e.g. multi-language fallback to default `en`).

### 2.2 Security Hardening Standards (Baseline for All Projects)
- **Authentication & Anti-Brute-Force:** Dual-key tracking (IP + Username), fail counter in cache, strict lockout (e.g. 5 failures $\to$ 15 min lock).
- **CAPTCHA Verification:** Enforce reCAPTCHA v2 / Turnstile on all sensitive endpoints (login, password reset, public inquiry forms) with server-side validation.
- **Cookie & Session Hardening:** `httpOnly: true`, `sameSite: Lax`, auto-`secure` on HTTPS. Separate namespaces for frontend/backend sessions.
- **File Upload Protection (5-Layer Defense):**
  1. Strict extension whitelisting (never trust client MIME).
  2. Binary header validation via image inspection functions.
  3. Deep payload scan against polyglot shellcode (`<?php`, `<?=`, `__halt_compiler`).
  4. Server-generated random filename + pixel-by-pixel re-encoding (GD/Imagick to WebP).
  5. Server-level execution denial (`.htaccess` / Nginx block script execution in upload dirs).
- **Data Sanitization & Query Safety:** 100% parameterized queries / Active Record bindings. Never concatenate unescaped user input into raw SQL. Sanitize and escape all HTML output (`Html::encode`).

### 2.3 UI/UX & Structural Parity Shield
- Never allow test/QA injection data to corrupt public layouts, mega menus, grids, or paginations.
- Preserve 1:1 design balance and layout grid columns.
- Ensure layouts handle extreme content lengths without breaking (overflow, ellipsis, sticky flex footers).
